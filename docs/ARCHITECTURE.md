# Architecture

## How it loads

Everything is client-side. `app.js` fetches `data/awards.json` on load, then loads every
award's `data_file` that exists. All awards in the registry are `"status": "active"` — some
have full recipient data, others (Kempegowda, Basava Puraskara, Padma, Sports honours, State
Film Awards, Smaller Honours) are active in the sidebar but their data files are still being
built, so they render with an empty roll. Switching awards re-renders in place — no page
reload. Awards are split one-per-entry (Arjuna/Dronacharya/Khel Ratna and the seven smaller
honours each have their own entry) rather than clubbed under a single row.

### The award registry (`data/awards.json`)

Each entry looks like this:

```json
{
  "id": "karnataka-ratna",
  "status": "active",
  "data_file": "data/awards/karnataka-ratna.json",
  "name_en": "Karnataka Ratna",
  "name_kn": "ಕರ್ನಾಟಕ ರತ್ನ",
  "desc_en": "Karnataka's highest civilian honour, conferred since 1992.",
  "desc_kn": "...",
  "recipients": 11,
  "year_range": "1992–2025",
  "level": "state",
  "wikidata_qid": "Q3630879",
  "has_location_data": false,
  "has_representation_data": false,
  "quickstatements_file": "data/quickstatements_karnataka_ratna.tsv",
  "hero_en": "Karnataka's highest civilian honour — instituted in 1992...",
  "hero_kn": "..."
}
```

- `status: "active"` awards are clickable in the sidebar nav. All twenty-three entries are
  active; nine have a real `data_file` with recipient records, fourteen are still data-less
  placeholders.
- `has_location_data` / `has_representation_data` gate whether the Map and Representation
  sections render for that award. Both are `true` only for Rajyotsava Prashasti right now.
- `hero_en` / `hero_kn` are the one-line blurbs under the H1 — falls back to `desc_en`/`desc_kn`
  if absent. Check the copy makes sense for a new award rather than letting it fall back silently.

### Per-recipient schema (`data/awards/<id>.json`)

```json
{
  "year": 1992,
  "name": "Kuvempu",
  "field": "Literature",
  "location": null,
  "wikipedia_url": "https://en.wikipedia.org/wiki/Kuvempu",
  "wikidata_qid": "Q3351108",
  "has_wikidata_statement": false,
  "source": "en+kn Wikipedia, cross-checked",
  "source_id": "wiki_karnataka_ratna",
  "source_url": "https://en.wikipedia.org/wiki/Karnataka_Ratna"
}
```

`has_wikidata_statement` is `true`/`false` if we checked Wikidata for the `award received`
(P166) statement pointing at this specific award, or `null` if we never checked. `null` and
`false` are rendered differently — don't conflate them.

`source_id` keys into `data/sources.json` (see below) and `source_url` is the canonical page
the record was taken from. Every record carries both — they power the public Sources & citations
section, the Wikipedia draft generator's `<ref>`, and the `S854` reference column in the
QuickStatements batches. Generated by `build_sources.py` in the repo root.

### The sources registry (`data/sources.json`)

One citation per distinct source page (Wikipedia lists and news articles), so a fix or a
fuller citation lives in one place instead of thousands of records:

```json
{
  "version": 1,
  "sources": {
    "wiki_raj_1966_1970": {
      "id": "wiki_raj_1966_1970",
      "title": "List of Rajyotsava Award recipients (1966–1970)",
      "url": "https://en.wikipedia.org/wiki/List_of_Rajyotsava_Award_recipients_%281966%E2%80%931970%29",
      "publisher": "Wikipedia",
      "language": "en",
      "kind": "wikipedia-list",
      "license": "CC BY-SA 4.0",
      "awards": ["rajyotsava-prashasti"]
    },
    "news_hindu_2023": {
      "id": "news_hindu_2023",
      "title": "ISRO Chairman Somanath, golfer Aditi Ashok among 68 people, 10 organisations chosen for Rajyotsava Award",
      "url": "https://www.thehindu.com/...",
      "publisher": "The Hindu",
      "language": "en",
      "kind": "news",
      "license": null,
      "date": "2023-10-31",
      "awards": ["rajyotsava-prashasti"]
    }
  }
}
```

- `kind` is `wikipedia-list` or `news`. Wikipedia sources carry `license: "CC BY-SA 4.0"`;
  news sources carry a publication `date` and `license: null`.
- `awards[]` lists which award(s) each source feeds, so the registry can be filtered per award.
- Rajyotsava year pages get ids `wiki_raj_<year>`; decade lists `wiki_raj_<start>_<end>`;
  `news_2023` → `news_hindu_2023`, `news_2025` → `news_indianexpress_2025`.

## Sections

The public page (`#public-view`) renders a three-column home grid: an award **sidebar** on the
left, the **map card** (map + timeline inside it) in the centre, and the **browse/filter list**
on the right. `app.js` `renderAwardNav()` draws every active award as a `.award-nav-item`
button; desktop the sidebar is sticky and vertically scrollable, and below `1000px` it flattens
to a horizontally scrollable row. The timeline lives *inside* the map card (`#timeline-section`
is a child of `.map-frame`, wrapped with the map in a `.map-stage` container) so the map legend
stays anchored to the map only, not the card. An `#admin` view (hash-routed via
`body.admin-mode` in `app.js`) holds the Wikidata-gaps, Wikipedia draft generator, provenance,
and representation sections. `applyRoute()` maps `#admin/wikidata|draft|provenance|representation`
to the corresponding section ids. Content hidden from public view (`#admin-view`) is hidden the
same way on every viewport — nothing public-only renders on mobile.

## The map (`js/map.js`)

`SanchiMap` loads district boundary GeoJSON
(`data/karnataka-districts.geojson`, `data/karnataka-state.geojson`) once, fills districts by
recipient count (choropleth), and overlays circle markers. `data/district_counts.json` provides
per-district counts and `other_locations` (outside-Karnataka recipients with coordinates) which
are plotted as teal markers. District names in the counts file are normalized against the
GeoJSON feature names (`map.js` `DISTRICT_ALIAS`: e.g. Chamarajanagar → Chamarajanagara,
Chikkaballapur → Chikkaballapura, Bagalkot → Bagalkote). Vijayanagara (a 2020 district) has no
2011-census polygon, so it shows as a circle marker only. `SanchiMap.refresh()` is called when
leaving admin mode to fix Leaflet sizing after `display:none`.

The map card's in-card legend (`#map-legend`) is absolutely positioned at the bottom of a
`.map-stage` wrapper that holds only the map, so it overlays the map (not the timeline below it)
and its `flex-wrap` prevents it overflowing the card on narrow viewports.

## Representation & data completeness (`js/representation.js`, `data/representation.json`)

Rajyotsava-only. Renders completeness bars (field/district/Wikipedia/Wikidata coverage), gender
by decade from Wikidata's P21 property, and a lowest-district list. Caste, community, and
religion are excluded by design — the sources rarely record them, and this project won't guess.

## Wikipedia draft generator (`js/wikidraft.js`)

For recipients without a Wikipedia article, generates a wikitext stub (infobox, intro,
categories) from the structured data. The intro's award claim carries a `<ref>` to the record's
`source_url` via a `{{cite web}}` template, so the source travels with the draft. Deliberately a
skeleton for a human to expand — not AI-written biography prose.

## Sources & citations (public page)

`data/sources.json` is the citation registry: one entry per source page, keyed by `source_id`.
Every recipient record carries `source_id` + `source_url` pointing at the page it was taken from.
The standalone `sources.html` page (driven by `js/sources.js`) renders all sources grouped by
award, joined with per-record `source_id` counts, listing each source's title, publisher,
language, and how many records cite it, plus a CC BY-SA 4.0 notice. Per the user's direction the
citations deliberately live on this separate page, not the main page.

## Extending this project

**To add a new award** (e.g. Kempegowda Award, a data-less active placeholder):

1. Research and pull recipient data — check both English and Kannada Wikipedia; cross-reference
   Wikidata for QIDs and the `award received` (P166) statement, same pattern as the existing
   awards.
2. Write `data/awards/<id>.json` in the schema above, adding a `source_id`/`source_url` to
   every record and registering the page in `data/sources.json` via `scripts/build_sources.py`.
3. Fill in `hero_en`/`hero_kn`.
4. If you have district-level location data, add a `district_counts.json`-style file, point to
   it via `district_data_file`, and set `has_location_data: true`.
5. Representation/completeness analysis is currently hand-rolled per award in `representation.js`
   / `app.js` rather than fully generalized — extending it to a second award means generalizing
   that code path or accepting it stays Rajyotsava-only.
6. If any recipients are missing the Wikidata statement, generate a `quickstatements_*.tsv`
   batch (see docs/DATA.md) and reference it via `quickstatements_file`.

**To add a new UI language:** add a language block to `DICT` in `js/i18n.js`, add a
`<button class="lang-btn" data-lang="xx">` to the nav in `index.html`, and add `xx` field-name
entries to the `FIELD_*` lookup if you want field categories translated too (otherwise they
fall back to English, which is safe but not ideal).
